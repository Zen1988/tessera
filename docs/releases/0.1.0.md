# TESSERA-Base 0.1.0

Workplace search now supports Tickets, entitled readable CMDB assets, FAQ and the
People directory. The visible search label is **Search**, with the complete scope
in its tooltip and accessible label.

- Assets require entitlement and a matching `TESSERA::CMDB::READ` assignment.
- `FAQApplication` is an optional, multiple-Application Dynamic Field on FAQ.
  Empty means applicable to all portal users; selected applications require an
  active matching SupportAssignment. Existing publication checks remain.
- Installation ensures native FAQ/reference-driver registration before field
  creation. A compatible legacy `ZFAQ-Application` is renamed using the same field
  ID, preserving values and administrator configuration. Ambiguous dual-name
  fields or conflicting handlers stop setup without overwriting data.
- People search is available to authenticated portal customers across companies,
  returning directory name and contact data only.
- Search type filters, paging, Enter handling and native input blur behavior are
  supported. Customer ticket/IPC authorization is retained.
- Version numbering rolls from `0.0.199` to `0.1.0`; the next patch is `0.1.1`.
  After `0.1.199`, use `0.2.0`. The separate GovernanceDB merge version is unchanged.

## Deployment toolkit correction

The release also provides TESSERA-Deployment-Cleanup-Update.zip (helper-only
update for an already prepared build folder) and the complete
TESSERA-Ubuntu26.04-Container-Toolkit.zip, both with checksum files.
The old fixed-name PVC create/upload block is removed from the current guides.
Install the helper update, then use:

```bash
python3 scripts/deploy-release.py --image docker.io/library/tessera:0.1.0-ubuntu26.04
```

This wrapper creates a unique temporary bundle PVC and enables cleanup after
successful native upgrade and both successful rollouts. Failed/uncertain runs
retain evidence. It does not sweep old volumes automatically. Four cleanup/helper
tests pass with0.1.0; real Kubernetes cleanup remains to be verified. The OPM,
existing runtime image and prepared matching upgrade bundle are unchanged by
this helper-only update.

## Remaining acceptance checks

- Native Linux fresh installation, upgrade and same-version reinstall, including
  real registration import and migration of existing FAQ values.
- Working-browser desktop/narrow/keyboard and visual acceptance. Local browser
  tools were unavailable or blocked by policy; no bypass or acceptance claim.
- Live Elasticsearch `faq`, `configitem` and `customeruser` index existence,
  population, source freshness, field mappings, matching and typing latency.
  Field registration does not create or populate these indexes.
- The owner reports the field appears in FAQ creation but is absent from the
  Dynamic Fields administration list. Admin filters/listing remain to be checked;
  no duplicate field creation is recommended.
- Consistent matching image/bundle and web/daemon workers under the existing
  deployment workflow. This release publication performs no live deployment,
  indexing, account grant or Kubernetes operation.

Use the normal package/source installation path. Do not manually create the field,
delete existing values, or replay an unresolved platform migration as a workaround.
