# TESSERA-Base 0.1.9

Fixes the network workspace returning400 with "Asset scope exceeds workspace budget" when the site has more than2000 Workload/NetworkNode candidates. The previous cutoff ran before customer entitlement checks, so unrelated assets could block an otherwise authorized user. The reported0.1.8 schemas, account grant and CMDB-read assignment passed diagnostics.

The workspace now scans candidate IDs in batches of500, anchored to the maximum initial ID. Each batch passes through native panel search and count/result consistency checks, then each asset still requires the centralized customer ConfigItemDetailAccessCheck before projection. Native Number ordering and scalar-bind contracts are preserved. There is no2000 candidate or authorized-asset cutoff and no silently truncated model. Complete authorized scope remains available for duplicate-IP rejection across batches.

A separate8MiB serialized authorized-model budget protects browser response size. Database/search failures and changed/inconsistent pages fail closed. Scan cost remains proportional to site candidates and centralized entitlement evaluation; live large-site timing requires acceptance. This patch does not add indexed entitlement joins or a paginated endpoint-selection UI.

No new fields, grants, schema or Navis request changes. Cumulative0.1.8 installer fix and0.1.7 default-graph fallback remain included. Install the0.1.9 OPM into the source installation before preparing/building/deploying a matching image and bundle with the0.1.9 toolkit.
