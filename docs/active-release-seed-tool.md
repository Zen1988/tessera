# Active release configuration tooling

TESSERA-Base 0.0.177 replaces stale release seeds using October 19 GeneralCatalog, CMDB and governance exports and the October 12 ticket type export. It packages 18 active ticket types, 26 implemented governance classes, 26 governance roles and 64 CMDB class/role definitions. Inactive entries and null role placeholders are excluded. Eleven active entries without definitions are planned features, confirmed by the owner; they are recorded as Pending, without fabricated definitions. References from implemented classes to missing/inactive roles still block generation.

Build a candidate with scripts/build_release_seed.pl CATALOG.yml CMDB.yml GOVERNANCE.yml TYPES.yml OUTPUT.json. The report records SHA256 source digests, exclusions, pending entries and errors. Errors prevent seed generation. Apply the validated candidate with scripts/sync_active_release_seed.pl MANIFEST.json SEED_DIRECTORY.

CMDB classes and roles are created through the native ClassImport API with IGNORE. GeneralCatalog seed does not precreate their labels, which would cause IGNORE to skip model installation. Governance classes/roles likewise use their normal bootstrap paths. Source-local Permission and ConfigItemGroup IDs are excluded from generic catalog preferences; model importers resolve exported group names locally. Existing disabled CMDB class/role labels are filtered before native import, whose own lookups discover only valid records. Existing deployed records remain untouched, including retired definitions and old package files; the obsolete Control-only seed is no longer read or shipped. No destructive retirement migration is included.

GeneralCatalog imports only active records using CreateOnly. Ticket type ensure preserves existing validity and fails on invalid seed or failed creation. CMDB import failure aborts bootstrap. This increment changes package bootstrap/seeds; it does not implement the Docker whole-platform startup runner, organization wizard, resets, CSR, Central ingestion or confidential disclosure.

Validation: five suites, 66 assertions. Tests exercise active selection, inactive dependency refusal, unknown validity, planned catalog entries, native importer selection and disabled-record preservation, and existing bootstrap merge behavior. Real Docker/database installation remains unverified. OPM is unsigned and not installed.
