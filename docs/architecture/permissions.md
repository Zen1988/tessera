# Permission boundaries

Customer CI discovery requires ContractEntitlement coverage of the applicable SupportProfile and that customer's corresponding SupportAssignment. Full detail additionally requires the matching TESSERA::CMDB::READ role. Company membership, owner fields, ticket participation or possession of an ID is not entitlement. Enforce backend boundaries across lookup, autocomplete, filters, APIs, lists and direct detail access.

TESSERA::* are reserved capabilities and never execute resolver scripts. PLATFORM::*, APPLICATION::* and TICKET::* may contain resolution programs; SUPPORT::* classifies assignments. Bootstrap roles are create-if-missing; existing roles remain administrator-owned.

Utilities visibility does not grant target access. External tools authenticate separately. Simulation requires an exact active customer grant plus CMDB read entitlement. Every referenced trace device is scope checked. By explicit owner decision, anonymous grey graph placeholders may expose the linked Application system name only for restricted devices; hidden CI identities/addresses/classes/attributes/links remain undisclosed. Detailed path evidence and recommendations stay withheld. This exception grants no CI or Application detail access. Recommendations never authorize changes.

Approved Major announcements deliberately expose a reviewed projection to active authenticated portal users, not ticket history, attachments, CI detail or workflow writes. Generic writes cannot modify protected change decisions.

Parser success is not authorization or approval. The executable-definition gateway still has documented gaps; see [security foundation](../policy-script-security-foundation.md). Do not claim signed publication/capability enforcement is complete.
