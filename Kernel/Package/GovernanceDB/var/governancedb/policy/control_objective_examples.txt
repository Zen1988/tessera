TESSERA ControlObjective policy examples
=========================================

The object and field names below are authored names. Internal database IDs must
never be placed in a policy. A missing field, failed conversion, or unsupported
expression evaluates to UNKNOWN and never silently satisfies a control.

ZRM-PolicyFilter
----------------

# This control applies only to active Change tickets.
APPLIES WHEN
    @TICKET.Type EQUALS "Change"
AND @TICKET.StateType DOES NOT EQUAL "closed"

ZRM-PolicyEvaluation
--------------------

# Actual execution must have started within the last calendar month interval.
REQUIRE
    @TICKET.ZTicket-ActualStart IS NOT EMPTY
AND DATETIME(@TICKET.ZTicket-ActualStart) IS ON OR AFTER 1 MONTH AGO

Numeric example
---------------

REQUIRE
    PRODUCT OF [NUMBER(@TICKET.ZRM-LikelihoodFactor), NUMBER(@TICKET.ZRM-ImpactFactor)] IS AT MOST 9

Initial executable grammar
--------------------------

- Roots: @TICKET and @CONTROLOBJECTIVE.
- Fields: native fields or exact Dynamic Field names.
- Logic: AND and OR at the start of a condition line.
- Comparison: EQUALS, DOES NOT EQUAL, IS EMPTY, IS NOT EMPTY,
  IS GREATER THAN, IS LESS THAN, IS AT LEAST, IS AT MOST,
  IS ON OR AFTER, IS ON OR BEFORE, CONTAINS, STARTS WITH, ENDS WITH.
- Conversion: NUMBER(...), STRING(...), DATE(...), DATETIME(...).
- Arithmetic: multiplication, division, and PRODUCT OF [...].
- Time: NOW and N DAYS/WEEKS/MONTHS/YEARS AGO.

Recursive GovernanceObject, ITSMConfigItem, and MELT traversal, named object
selection, collections, schedules, business calendars, and LET variables remain
reserved grammar. Until implemented, using them returns UNKNOWN.

Failure-to-risk behavior
------------------------

Control failure does not create a service or workflow ticket. ZRM-CreateRisk on
the ControlObjective explicitly enables risk creation. ZRM-RiskClass selects the
target using ObjectType.Class syntax, normally MELTObject.Risk.

The ConfigItem Control's ZRM-FieldAssignment contains programmable assignments:

SET @MELTObject.Risk.MELT-Control THIS
SET @MELTObject.Risk.MELT-RiskStmt @CONTROLOBJECTIVE.ZRM-RiskStmt

THIS is the current ConfigItem Control ID. Every target Dynamic Field is checked
against the selected object type. Values may be literals or expressions supported
by the policy value grammar. The Control link makes repeated failed evaluation
idempotent: an existing risk for the same Control and class is reused.

Manual controls become AWAITING_EVIDENCE when due. They never create a ticket
automatically. An existing process may still invoke ZRMControlEvaluate with its
ticket as execution evidence; a Fail result then follows the same opt-in risk rule.

Control cycle examples
----------------------

- 1 year 1 time
- 1 year 2 times
- 3 months 1 time
- daily, weekly, monthly, quarterly, annually
