# Integration boundaries

Integration onboarding configures HTTPS origins, operator-issued credentials/mounted secret references, scopes and identity metadata. Native adapters own authorization, bounded payloads, saved evidence and continuation.

- [Navis](navis.md): network evidence, topology, trace and recommendation drafts.
- [AWX](../awx-managed-onboarding.md): authorized automation and durable callback.
- [NetXMS](../netxms-integration.md): configured monitoring reads.
- [Utilities](../utilities.md): browser launch with destination-owned authentication.

Authentication success does not prove source permissions, mappings, inventory readiness or execution authority. Never store secrets in scripts, exports, examples or customer URLs. Only safe GETs may have bounded retries; uncertain POSTs require reconciliation.

Script syntax does not create a callable capability. See [offline authoring](../scriptengine/README.md) for caller-specific execution limits.
