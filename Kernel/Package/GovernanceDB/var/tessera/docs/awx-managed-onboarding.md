# Managed AWX bearer-token onboarding — Base189

Use Admin → Integration onboarding (Action=AgentTESSERAIntegration), then select AWX bearer token. The existing native HTTP::REST header method remains supported; this adds a managed alternative without modifying OTOBO core authentication dropdowns.

1. Have the AWX administrator issue a token to restricted tessera.integrator. Its RBAC must permit approved template launches and result reads; do not grant system administrator or device-credential management. Token scope must allow launch POSTs. TESSERA does not create AWX users, roles or tokens.
2. Project the exact token into /run/tessera-secrets/awx-api-token in BOTH web and daemon, using the existing restricted secret mount. No newline, spaces or header syntax; enter only the token in that file. The native secret reader enforces its filesystem protections. Do not put the token in YAML, tickets, URLs, Web Service headers or configuration exports for this managed connection.
3. Create a new managed connection name, e.g. ansible.awx.managed. Existing administrator-owned ansible.awx/ID4 is not adopted or overwritten. Origin=https://awx.ncs.local. SecretName=awx-api-token. Leave TokenURL, ClientID and Scope empty. AWX routes/invoker types are supplied by the preset.
4. Test authentication: one read-only GET /api/v2/me/ must return a single authenticated identity. This checks token/HTTPS reachability, not template execute permissions. Enable and save only when successful. No job is launched by onboarding. TLS certificate and hostname validation remain mandatory; mount/trust AWX's CA in the existing system trust bundle. Redirects are not followed.
5. Record the NEW saved WebserviceID; update the trusted ScriptEngine AllowedCalls binding to that ID. For first proof use the owner-selected template35 (System-AWX Heartbeat, Demo Inventory). Verify live synced playbook matches playbooks/system/awx/awx-heartbeat.yml: localhost/local, no device credentials, publishes artifacts.tessera_heartbeat. It has no callback, so use JobLaunch, RETURN EXTERNAL.LAUNCH.JobID, and read/poll the saved JobID rather than rerunning YAML.
6. Then test a separate callback-capable template and inventory sync. This execution preset registers8 job/workflow/status/output invokers, not inventory-write capabilities. Existing separate restricted inventory connection remains unchanged. Persistent agent-side Automated Task publication/provider binding is a separate unverified path; the existing authorized AutomationTest runner is the current ScriptEngine acceptance surface.

The managed configuration stores only provider/secret reference. Token is read each request, so mounted secret rotation is effective without native token-store migration. Static PATs are not refreshed by client-credentials/OIDC; replace/revoke through AWX administration before expiry. There is no automatic static-token401 retry. All launch POSTs are single-attempt; uncertain outcomes require reconciliation. Transport error text is sanitized and never passes Authorization diagnostics to GI debugging. Other AWX responses/callback variables and native requester debug output may still be sensitive: use error-level debugging and restrict configuration/history access.

Known first-deployment steps: generate token; add dedicated secret mount; confirm AWX CA; install189; verify new preset; configure managed service and exact allowed-call binding; run script once and capture terminal job/artifact. No live token/config/job was created during implementation.

Upgrade/reinstall: file-only extension, no new schema/DynamicFields or automatic connection imports. Existing Navis/Generic managed connections, legacy AWX REST service, credentials and histories are preserved. Fresh/upgrade/reinstall deploy the same module payloads.189 also packages the separately requested Elasticsearch compatibility replacement at Custom/Kernel/System/Elasticsearch.pm with existing CMDB multitenancy authorization retained; check native package file ownership and mounted/init overlay sources on live installation so an older extension does not restore it. Native live fresh/upgrade/reinstall acceptance remains required.
