# Validation and acceptance

Targeted mock tests establish contract and failure handling, not live DB/deployment acceptance. Browser fixtures establish local layout/interactions, not complete production theme compatibility.

Simulation checks cover NetworkSimulationAccess, CustomerNetworkSimulation, IntegrationOnboarding and NavisPreparation with native library paths; CustomerNetworkSimulationUI checks the actual page script. Verify strict JSON, grants, endpoint scope, path withholding, named lookup, durable POST intent/replay refusal and GET-only receipt reconciliation.

Verify decoded OPM bytes, baseline immutability, unchanged hooks and matching image/bundle metadata. Offline pack checks include file hashes, exact native exports, Set round-trip and actual parser examples; YAML acceptance alone is insufficient.

Native acceptance remains required: Linux fresh/upgrade/reinstall, real DB concurrency/failure, site overrides, all-worker activation, real customer/IPC/manager roles, production theme/mobile/keyboard, Navis matching Navis named-topology/progress migrations/source permissions, mappings and partial/ambiguous evidence. HTTP200 is not connectivity or execution approval.
