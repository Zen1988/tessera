# TESSERA-Base 0.1.2

Native ticket type remains Change. The installer invalidates the obsolete Change::Major type while retaining its ID and history; historical tickets are not automatically reclassified or announced.

Two protected Ticket Dropdown fields replace subtype-based decisions:

- ChangeType: Normal (default), Standard, Emergency.
- ChangeClassification: Normal, Not-Assessed (default), Major.

Requester creation and generic edits cannot set these fields. Configurable change-manager/CAB groups manage decisions after completed assessments; no CAB group is granted by default. Existing IPC write membership overrides group/ticket scope and can explicitly override assessment completion with recorded reason. IPC cannot bypass change approval. Decisions use transactional saves, private evidence, live database verification and replay protection.

Selecting Major prepares a public snapshot. Normal change approval activates it automatically; there is no separate publication checkbox. Workplace links to a dedicated read-only announcement available to active authenticated portal customers independently of ordinary ticket grants. It shows reviewed summary/description, requester and affected CI names, environment, application, schedule and submitted ZCH-* runbook phases. It exposes no ticket history, attachments, private assignment columns or CI detail links. Missing approval policy, withdrawal, demotion or changed source context fails closed.

Install this OPM through the normal package installation path on the source host before preparing the next image. Use the versioned 0.1.2 container toolkit and verify its .zip.sha256 file. Activate the protected Dropdown driver consistently across all web/daemon workers; retain the matching generated upgrade bundle. Do not copy generated ZZZ files from another environment. See docs/change-classification.md for configuration and acceptance details.
