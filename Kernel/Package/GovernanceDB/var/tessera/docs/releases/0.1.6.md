# TESSERA-Base 0.1.6

Reviewed against published Navis0.1.1 commit ed4ba3e312bd24b0afabc2a2b2949e0aaa9c75a8 on2026-11-23. The19-path OpenAPI differs from the previously tested contract only in info.version. Request/response semantics remain compatible.

Fixed TopologyCreate to accept documented HTTP201. Previously a successful named/default topology creation was reported as uncertain because the transport expected200. Trace and refresh still expect200; ingestion expects202. No POST replay was added. Existing managed Navis configurations receive the fixed registry at runtime validation; normal native edit/save refreshes persisted route metadata without changing credentials.

Customer users enter no graph ID, UUID or label. Default traces omit graph selectors; an authorized Application choice resolves the administrator-maintained Application Navis label server-side. Returned build UUIDs remain internal frozen analysis evidence. Forged raw graph selector parameters do not enter the outgoing customer request.

Also normalizes numeric-looking CMDB identifiers at the JavaScript presentation boundary so saved endpoint selections and node links work consistently with DOM string values. Opaque string IDs, including leading zeros, are preserved.

Includes cumulative0.1.5 behavior. The full AWX discovery scheduler and CMDB membership/topology-creation automation remain separate future work. Native fresh/upgrade/reinstall, real Navis/AGE/source mappings and production deployment acceptance remain required. No image build or deployment performed.

Use the matching0.1.6 OPM, container toolkit and offline authoring pack. Install the OPM normally into the source installation before a fresh prepare/build. Do not replace Config.pm or manually copy generated ZZZ files for this change.
